If you're using UPnP mode in PeakHour to talk to your router and you know or suspect the reporting is inaccurate, we recommend going through the steps below to test your router with a third-party UPnP client called MiniUPnP.

**MiniUPnP** is a free, lightweight UPnP client. You can use MiniUPnP to poll your router's UPnP stack and get a report of what information it is sending back — independently of PeakHour.

To install [MiniUPnP](http://miniupnp.free.fr) on your Mac, follow these steps:

1.  Open **Terminal** (type 'Terminal' into Spotlight).

2.  Install [Homebrew](https://brew.sh) if you don't already have it:

    ```sh
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
    ```

    (Note: if you prefer to use a different package manager, such as MacPorts, skip this step.)

3.  Install miniupnpc:

    ```sh
    brew install miniupnpc
    ```

Once `upnpc` is installed, run the following command to query your router:

```sh
upnpc -s
```

If your router is responding to UPnP requests correctly, you should see output similar to this:

```

for more information.

desc: http://192.168.1.1:2189/rootDesc.xml

Found valid IGD : http://192.168.1.254:49000/upnp/control/WANIPConn1

Status : Connected, uptime=689041s, LastConnectionError : ERROR_NONE

MaxBitRateDown : 12842000 bps (12.8 Mbps) MaxBitRateUp 1031000 bps (1.0 Mbps)
ExternalIPAddress = 202.200.200.201
Bytes: Sent: 891855735 Recv: 2321636851
Packets: Sent: 3929125 Recv: 4125142
```

Here are some tips for interpreting the output:

  - Most important is the **Bytes** line. This is what PeakHour needs in order to calculate the information it displays (graphs, current upload/download speeds, and usage).

  - Run the command a few times over a few seconds and observe any changes to the `Sent:` and `Recv:` byte counts.

  - If the Bytes line is 0, or stuck around 4,294,967,295, then it's likely that your router has a bug with UPnP or isn't properly implementing the specification.

  - (Advanced) If the byte values appear to be incrementing but you suspect they're not correct, do the following:

      - Note the values, then run the command again a few seconds later and note the new values.

      - Subtract the first from the second and divide by the number of seconds you waited. This gives you the average bytes/sec.

      - (Optional) Use a site like [speedtest.net](https://www.speedtest.net) to generate a known amount of throughput to compare against.
